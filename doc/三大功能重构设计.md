# MantaPhotos 三大功能重构设计：自动标签 · 逆地理编码 · 语义搜索

目标：把当前已搭好「骨架」但与既定设计有偏差的三项能力，重构到**可用、可标定、可搜索**的最终态：

1. **自动打标签**——从「只存 Vision 英文原始标签」升级为「年份 + 国家 + 城市 + 内容（中文词表零样本）」的**槽位化、最多 10 个标签**体系，支持视频抽帧聚合，支持标签搜索。
2. **GPS → 城市/位置**——从「逐张请求 `MKReverseGeocodingRequest`」升级为「**坐标网格聚类去重 + 状态机限流 + 全量→增量断点续跑**」，并把国家 / 城市**回写为可搜索标签**。
3. **语义搜索**——补齐缺失的「**阈值过滤 + RRF 混合检索 + 重排**」，先修正向量评分一致性 bug（cosine + L2 归一化），并把多模态模型默认值定为 **MobileCLIP2（可切 JINA / 后期 Gemma，同一时间只启用一个）**，Apple 图像特征向量退回「找相似」专用链路。

> 本文是**设计与改造清单**，所有结论基于对当前代码的实际盘点（文件 / 符号已标注）。对应分享对话《mantaPhotos向量模型调研》中敲定的四点决策。
>
> 文档关系：本文是工程实现清单；产品/功能层定义见 `SPEC.md` §9.9；总体向量设计见 `doc/Mac应用实现方案.md` §3.6 / §8.6。三处已加交叉引用。

## 0. 一句话结论（先看这条）

三项能力的**数据通路都已存在**，差距集中在「**语义层缺失**」与「**调用策略未优化**」两类：

- 打标签：`TaggingProcessor` 只把 `VNClassifyImageRequest` 的英文 identifier 原样落库（`tag_id = "vision:<key>"`、`display_name = key`），**没有年/国/城结构化槽位、没有「最多 10 个」约束、没有中文词表零样本、没有视频抽帧**。
- 逆地理：`GeocodingProcessor` **逐张** new 一个 `MKReverseGeocodingRequest`、`sleep(300ms)`，**没有坐标聚类去重**——大库会被限流拖垮；且 `photo_locations` 里的 country/locality **没有回写到 `photo_tags` / FTS**，所以"按城市搜索"实际搜不到。
- 语义搜索：`semanticSearch` 已能「文字→向量→KNN→结果」，但**无阈值、无 RRF、无重排**；更底层有一个**评分一致性 bug**——`vec0` 表建表时未声明 `distance_metric=cosine`、入库向量未 L2 归一化、`SQLiteVecIndex.nearest` 返回 `-距离`（L2）、暴力降级路径却返回**余弦相似度**，两条路打分口径不一致 → **阈值无从标定**。这是必须先修的地基。

## 1. 现状盘点（与设计的逐项对照）

### 1.1 自动标签

| 维度 | 位置 | 现状 | 与设计的差距 |
| --- | --- | --- | --- |
| 内容标签来源 | `Infrastructure/Analysis/AnalysisProcessors.swift` → `TaggingProcessor.classify` | `VNClassifyImageRequest`，`confidence >= 0.1`，`prefix(8)`，存英文 identifier | 设计走 **JINA/MobileCLIP2 中文词表零样本**（图片向量 ↔ 词表向量余弦）；Vision 仅作可选补充 |
| 标签落库 | `Infrastructure/Database/AnalysisDataRepository.swift` → `upsertTags` | `tag_id="vision:<key>"`、`display_name=key`、`category='scene'`、`source='vision'` | 缺 `type`（year/country/city/content）区分；`display_name` 是英文 |
| 年份标签 | （缺失） | 无 | 应由 `creation_date` 确定性派生 |
| 国家/城市标签 | （缺失，仅存在 `photo_locations`） | `upsertLocation` 只写 `photo_locations`，**未回写 `photo_tags`** | 应由逆地理聚类结果回填为 `type='country'/'city'` 标签 |
| 「最多 10 个」 | （缺失） | `prefix(8)` 纯内容标签，无槽位 | 设计：1 年 + 1 国 + 1 城 + ≤7 内容 |
| 中文词表 | （缺失） | 无 `label_vocab` 表 | 需分层中文词表 + 别名 + 每模型一张词表向量表 |
| 视频 | `Domain/PhotoAnalysisTask.swift` → `AssetImageLoader.imageData` | 视频走 `requestImageData`（取 poster 单帧或失败） | 设计：`AVAssetImageGenerator` 抽多关键帧 → 逐帧打标 → 聚合 |

### 1.2 GPS 逆地理编码

| 维度 | 位置 | 现状 | 与设计的差距 |
| --- | --- | --- | --- |
| 反查 API | `AnalysisProcessors.swift` → `GeocodingProcessor.reverseGeocode` | `MKReverseGeocodingRequest`（macOS 26）+ `MKAddressRepresentations` ✅ 已正确选型 | 保持，符合决策②「全用 Apple API」 |
| 请求粒度 | `GeocodingProcessor.process` | **逐张** new 请求 + `sleep(300ms)` | 设计：**坐标网格（~100m）聚类去重**，同一地点只请求一次 |
| 去重表 | （缺失） | 无 `coord_clusters` | 需新建聚类表，作为实际发起请求的对象 |
| GPS 提取 | `GeocodingProcessor.coordinate` / `exifLocation` | 系统源 `PHAsset.location`；本地图片 `kCGImagePropertyGPSDictionary`（含 N/S/E/W 换算）✅ | 视频未读容器 GPS（`AVMetadata` `.commonKeyLocation` / ISO6709）—待补 |
| 状态/重试 | `photo_analysis_state(kind='geocoding')` | 仅幂等「已处理」标记，无 `pending/done/failed` + 退避 | 设计：聚类级 `status` + `retry_count` + 指数退避，支持断点续跑 |
| 回写搜索 | `upsertLocation` | 只写 `photo_locations`，**不进标签/FTS** | 国家/城市应回写 `photo_tags`(type=country/city) 与 `photo_search_documents.place` |
| geohash | （缺失） | `photo_locations` 无 geohash | 设计：加 geohash 供地图聚合 / 附近查询 |

### 1.3 语义搜索

| 维度 | 位置 | 现状 | 与设计的差距 |
| --- | --- | --- | --- |
| 向量存储 | `Infrastructure/Database/VectorIndex.swift` → `SQLiteVecIndex.ensureTable` | `vec0(photo_id, embedding float[dim])`，**未声明 `distance_metric=cosine`**（默认 L2） | 必须建成 `cosine` |
| 入库归一化 | `AnalysisDataRepository.upsertEmbedding` | 直接存原始向量，**无 L2 归一化** | 设计：入库前 `vDSP` L2 归一化 |
| KNN 打分 | `SQLiteVecIndex.nearest` vs `AnalysisDataRepository.nearest` 暴力路径 | sqlite-vec 返回 `score = -distance`（L2 距离）；暴力路径返回 `cosineSimilarity` | **两条路口径不一致** → 阈值无法统一标定（核心 bug） |
| 文字语义搜索 | `App/PhotoLibraryViewModel.swift` → `semanticSearch` | textEmbedding → `nearest(limit:300)` → 直接展示 | **无阈值过滤、无 RRF、无重排** |
| 以图搜图 | `PhotoLibraryViewModel.searchSimilar` | Apple FeaturePrint KNN ✅ | 保持，作为「找相似」独立链路 |
| 默认多模态模型 | `Domain/Embedding.swift` → `EmbeddingProviderRegistry.defaultKey = "apple.featureprint"` | 默认 = Apple 图像特征向量（**不支持文字查询**） | 决策④：默认应为 **MobileCLIP2**；Apple FP 退为「找相似」专用 |
| MobileCLIP2 | （缺失） | 只有 `AppleFeaturePrintProvider` + `CustomMLXEmbeddingProvider`（JINA 走 MLX） | 需新增 Core ML 版 `MobileCLIP2Provider` 作默认 |
| 模型阈值配置 | （缺失） | `embedding_spaces` 无 `sim_threshold` | 设计：每模型独立标定阈值，存注册表 |
| 混合检索 | `Infrastructure/Database/SearchRepository.swift` | 仅 FTS 关键词 + 结构化过滤；**稠密向量未进主搜索** | 设计：稠密(语义) ⊕ 稀疏(FTS/标签) RRF 融合 |

> 关键澄清（来自分享对话）：所存「Apple 自带」向量是 `VNGenerateImageFeaturePrintRequest` 的**图像-only** 特征，代码已正确标注 `supportsTextQuery=false`，**不能打字搜图**，定位「找相似 / 去重」。打字搜图只能走多模态模型（MobileCLIP2 / JINA）。

## 2. 设计目标与边界

**目标**：统一为「**资产处理流水线 + 统一搜索层**」。三件事产出都汇入同一套标签 / 位置 / 向量存储，搜索层在 SQL 与应用层融合。

**两条向量链路分离（重要重构）**：当前架构用**单一** `vectorModelKey` 同时驱动「向量索引任务」与「搜索」。重构后明确拆为两条独立空间：

- **相似空间（固定）**：Apple `VNGenerateImageFeaturePrint`（768 维，图像-only），**始终索引**，只服务"找相似 / 去重"，与模型切换无关。
- **语义空间（可切，同时只启用一个）**：默认 **MobileCLIP2**，可切 **JINA**，后期可插 **Gemma**。服务"打字搜图"与"中文词表零样本打标"。切换 = 触发一次后台全库重索引（词表向量同时重算）。

**边界**：
- 决策②：逆地理**全用 Apple API**，靠聚类去重 + 限流控制请求量，不引入离线 GeoNames。
- RRF 的"两路"= **当前启用的语义模型 ⊕ 标签/FTS 关键词**，**不**把 Apple FeaturePrint 混进来（不在文本空间，等于喂噪声）。
- MobileCLIP2 / JINA / Gemma 的实际维度需在接入时回填（本文 schema 用占位维度，建表按空间记录的 `dimension` 动态生成，不写死）。

## 3. 数据库变更（migration 7 起）

沿用 `DatabaseMigrator` 的版本化迁移（重构前最高 version 6 = `p2_embeddings_and_type`）。**按里程碑拆分迁移**（每个 M 一个版本，而非一个大 bundle）：M2 = **version 7 `geo_coord_clusters`**（已落地），后续 M3/M4/M5/M6 各自追加 version 8、9…。所有新表 `create table if not exists`，对存量行做回填，保持与 `photo_assets.id` 的外键关系。

### 3.1 标签：扩展 `photo_tags` 语义 + 新增中文词表

```sql
-- photo_tags 增加 type 维度（year/country/city/content），区分槽位
alter table photo_tags add column tag_type text not null default 'content';
-- 既有 vision 标签视为 content；后续 year/country/city 由派生逻辑写入

create index if not exists idx_photo_tags_type on photo_tags(tag_type, tag_id);

-- 分层中文标签词表
create table if not exists label_vocab (
  id integer primary key,
  value text not null unique,          -- 中文标签，如 "海滩"
  parent_id integer references label_vocab(id),  -- 层级：大类/子类
  aliases_json text,                   -- 同义词
  enabled integer not null default 1,
  updated_at text not null
);

-- 词表向量：必须与「当前启用语义模型」同空间，故每模型一张（表名按 space_key 动态生成，
-- 复用 SQLiteVecIndex.tableName 规则：vec_label_<sanitized_space_key>）
-- 例： create virtual table vec_label_mobileclip2 using vec0(
--        label_id integer primary key, embedding float[<dim>] distance_metric=cosine);
```

> 年份、日期、国家、城市，由照片本身的时间、地理信息查询出，无需在标签表中添加数据。匹配标签时，内容按相似度降序，只取置信度超过阈值的内容。如果超过阈值的标签内容超过5个，最多取5个标签。

### 3.2 逆地理：坐标聚类表 + `photo_locations` 增列

```sql
-- 坐标网格聚类：实际去发起 geocode 请求的对象（控制 Apple API 调用量的核心）
create table if not exists coord_clusters (
  id integer primary key,
  grid_lat real not null,              -- 经纬度四舍五入到 4 位小数（~10m 网格）
  grid_lon real not null,
  country text,
  country_code text,
  admin1 text,                         -- 省/州
  city text,
  place_name text,                     -- POI/地标（MKAddressRepresentations）
  status text not null default 'pending',  -- pending|done|failed
  retry_count integer not null default 0,
  last_attempt text,
  updated_at text not null,
  unique(grid_lat, grid_lon)
);
create index if not exists idx_coord_clusters_status on coord_clusters(status);

-- photo_locations 引用聚类 + geohash + 海拔（保留既有 country/locality 等列，逐步以聚类回填）
-- 海拔为每张照片属性（同网格不同照片海拔不同），故存 photo_locations 而非聚类。
alter table photo_locations add column cluster_id integer references coord_clusters(id);
alter table photo_locations add column geohash text;
alter table photo_locations add column altitude real;
create index if not exists idx_photo_locations_cluster on photo_locations(cluster_id);
create index if not exists idx_photo_locations_geohash on photo_locations(geohash);
```

某资产的国家/城市 = 其 `cluster_id` 对应聚类的 `country`/`city`，geocode 完成后**批量回填**到 `photo_locations`（denormalize，供详情页/筛选直接查询）与 `photo_search_documents.place`；**不写入 `photo_tags`**（年份/日期/国家/城市均不进标签表，按 §3.1 设计直接查询得出）。

### 3.3 语义：模型阈值配置

```sql
-- embedding_spaces 增加每模型独立标定的相似度阈值与角色
alter table embedding_spaces add column sim_threshold real not null default 0.25;
alter table embedding_spaces add column role text not null default 'semantic';
-- role: 'semantic'（打字搜图/零样本打标，同时只一个 active）| 'similarity'（Apple FP，固定）

-- 混合检索参数入 app_settings（可调）
insert or ignore into app_settings(key, value, updated_at) values
  ('search.activeSemanticModel', 'mobileclip2', strftime('%Y-%m-%dT%H:%M:%fZ','now')),
  ('search.rrfK', '60', strftime('%Y-%m-%dT%H:%M:%fZ','now')),
  ('search.minFusedScore', '0.0', strftime('%Y-%m-%dT%H:%M:%fZ','now'));
```

> `app_settings('analysis.vectorModel')`（migration 6 写入的 `apple.featureprint`）语义改变：今后专指「相似空间」固定模型；「语义空间」启用项改用 `search.activeSemanticModel`。迁移时不删旧键，新增键并行。

## 4. 功能一：自动标签重构

### 4.1 标签来源拆分

```
年份/日期 ← creation_date 直接查询（无需 AI，不写入标签表）
国家/城市 ← photo_locations（功能二回填，不写入标签表）
内容     ← 当前语义模型零样本：图片向量 ↔ vec_label_<model> KNN，按相似度降序，
           只取 confidence ≥ sim_threshold 的内容，最多 5 个    type=content source=zeroshot
```

年份、日期、国家、城市**不进 `photo_tags`/`tag_definitions`**：详情页与筛选直接从 `photo_asset.creation_date`、`photo_locations`（country/administrative_area/locality/place_name）查询得出。`photo_tags` 只承载 §4.2 的内容标签。

### 4.2 `TaggingProcessor` 重构（`AnalysisProcessors.swift`）

- 改名/分拆为 `ContentTaggingProcessor`：取图 → `provider.imageEmbedding` →（复用已存的向量，避免重复推理）→ 与 `vec_label_<activeModel>` 做 KNN → 过该模型 `sim_threshold` → 按相似度降序最多取 5 个 → 写 `type='content'`。
- 年份/日期/国家/城市不再有对应的 Processor 写标签——分别由 creation_date（确定性）与逆地理聚类回填（功能二）落在 `photo_asset`/`photo_locations`，查询时直接读取。
- `upsertTags` 扩展签名带 `tagType` 与中文 `displayName`（取自 `label_vocab.value`）。
- Vision (`VNClassifyImageRequest`) 作为**可选增强开关**（`app_settings('analysis.visionEnabled')` 已存在），默认关闭，启用时其输出并入 content 候选再统一过阈值。

### 4.3 词表维护

- 内置一份分层中文词表（大类/子类 + 别名），随包发布，写入 `label_vocab`。
- 切换语义模型或首次启用时，后台为 `label_vocab` 每条算向量写 `vec_label_<model>`；词表改动只重算被改条目。
- **词表向量与图片向量必须同一模型 / 同一预处理**，否则空间不一致。

### 4.4 视频抽帧

- `AssetImageLoader` 增加视频分支：`AVAssetImageGenerator`（已按 9.9bis 用异步 `image(at:)`）抽 N 帧（按时长/场景）→ 逐帧 `imageEmbedding` → 帧向量均值池化为一条资产级向量（存 `photo_embeddings` 作 PK 行）→ content 标签按帧标签并集 + 频次/置信度排序。

## 5. 功能二：逆地理编码重构

### 5.1 聚类去重流水线

```
1) GPS 提取（三源）
   系统源: PHAsset.location  ·  本地图: kCGImagePropertyGPSDictionary  ·  视频: AVMetadata location
2) 网格化：grid_lat/lon = round(lat/lon, 4)（~10m）→ upsert coord_clusters，photo_locations.cluster_id 关联；同时存 altitude（海拔）与 geohash
3) geocode 仅对 coord_clusters.status='pending' 的**唯一聚类**发起 MKReverseGeocodingRequest
   → 低 QoS 串行队列限流（保守 ≥1 次/秒起步）；失败 retry_count++ 指数退避，写 status=failed
4) 成功：回填聚类 country/admin1/city/place_name，status=done
   → 批量把该聚类下所有 photo 的地名 denormalize 到 photo_locations + 更新 photo_search_documents.place
     （不写入 photo_tags：国家/城市按 §3.1 设计直接查询 photo_locations 得出）
```

调用量量级：一次旅行几十上百张照片落在同一 ~100m 网格 → 只发 1 次请求，API 调用量降 1–2 个数量级，从根本上规避限流。

### 5.2 全量 → 增量断点续跑

- 驱动键从 `photo_analysis_state(kind='geocoding')`（逐张幂等）改为 **`coord_clusters.status`**（聚类级）。
- 重启后只取 `pending`/`failed` 聚类 + 新增坐标，天然支持「先全量、之后只跑未完成 + 增量」。
- macOS 无 iOS `BGTaskScheduler`，沿用 `TaskCenter` 的常驻低优 `Task` + 状态持久化即可断点续跑（已具雏形，改造其 `GeocodingProcessor` 取批逻辑指向聚类表）。

### 5.3 地址本地化

- 继续用 `MKAddressRepresentations`（`cityName`/`regionName`/`region.identifier`→本地化国家名），**不自己拼地址串**；`preferredLocale` 跟随 `TaskCenter.localeIdentifier`（已实现）。

## 6. 功能三：语义搜索重构

### 6.1 先修地基：向量评分一致性（P0，阻塞项）

1. `SQLiteVecIndex.ensureTable` / 词表表建表加 `distance_metric=cosine`。
2. `AnalysisDataRepository.upsertEmbedding` 入库前对向量做 **L2 归一化**（`Accelerate/vDSP`），`VectorMath` 加 `normalize`。
3. 统一 `nearest` 返回**余弦相似度** `sim = 1 - cosine_distance`（sqlite-vec 路径）与 `cosineSimilarity`（暴力路径）口径一致，`VectorMatch.score` 语义统一为「越大越相似、范围约 [-1,1]」。
4. 既有向量需**重建索引**（已有 `clearSpace` + 重建能力）一次，确保归一化与 cosine 表生效。

> 没有这一步，阈值（`sim_threshold`）无从标定，RRF 的稠密路也不可信。这是功能三第一优先。

### 6.2 模型保留策略 + Provider + 默认值切换

**决策：两个模型都保留，各管一种「相似」（不是冗余）。**

- **Apple FeaturePrint（固定相似空间）** → **去重 / 近重复**。它捕捉**视觉/结构相似**，连拍、裁剪、调色版会贴得极近，是去重该用的特性；系统自带、零模型文件、立即可用。
- **MobileCLIP2（语义空间，默认）** → **打字搜图 + 中文词表零样本打标 + 「语义找相似」**。它捕捉**语义相似**（不同照片只要内容都是"海边日落"就接近）。
- 用 CLIP 向量做去重会误判（一堆"语义像但实为不同照片"被判重复），故**去重仍走 FeaturePrint**，CLIP 只做"内容相近"。

**Provider 改造：**

- 新增 `MobileCLIP2Provider: EmbeddingProvider`（Core ML text/image encoder，跑 ANE，离线），`modality=.multimodal`、`supportsTextQuery=true`、`isAvailable` 视模型文件是否就绪。
- `EmbeddingProviderRegistry`：区分 `similarityProvider`（固定 Apple FP，始终索引）与 `semanticProvider(forKey:)`；`allDescriptors` 同时含两类。
- 语义空间**默认 = MobileCLIP2**；**用户可自定义切换为 JINA V5（1024 维，走已有 `CustomMLXEmbeddingProvider` + MLX 运行时）替代 MobileCLIP2**，后期可插 Gemma。**同时只启用一个语义模型**，切换 = 触发一次后台全库重索引（词表向量同时重算）。Apple FP 相似空间与切换无关，始终可用。

**MobileCLIP2 变体与维度（来自官方 ml-mobileclip）：** S0/S2/B/S3/S4 五档，越大越准、越慢——S0 ≈71.5% / S2 ≈77.2% / B ≈79.4% / S3 ≈80.7% / S4 ≈81.9%（ImageNet zero-shot），S4 用约一半参数达到 SigLIP-SO400M 精度。**「更好的效果」靠选更大的变体，不是靠更大的向量维度**。S0/S2/B 共享嵌入维度均为 **512**；S3/S4 文本编码器更大（123.6M），投影维度更高，按其 model card 回填（建表已按 `embedding_spaces.dimension` 动态生成，不写死）。

**默认变体 = MobileCLIP2-B（已定）**：512 维、ImageNet zero-shot ≈79.4%，图像编码器 86.3M（比 S2 的 35.7M 大、更准），图像延迟约 10.4ms。模型来源 `timm/MobileCLIP2-B-OpenCLIP`（OpenCLIP 标识 `MobileCLIP2-B`），接入需转 Core ML（image + text encoder 两个）。`EmbeddingSpaceDescriptor` 建议：`key="apple.mobileclip2_b"`、`dimension=512`、`modality=.multimodal`、`supportsTextQuery=true`。追求更高精度可后续切 S4（维度按 model card 回填，触发重索引）。

**前瞻（macOS 27 / Core AI）：** WWDC 2026（2026-06）Apple 宣布以 **Core AI** 取代 Core ML 作为端侧推理新框架，但二者**共存、无弃用时间表、既有 `.mlmodel` / `MLModel` 继续可用**（见 §8 风险表）。故 MobileCLIP2 现按 Core ML 接入无碍，后续平滑迁移 Core AI。

### 6.3 混合检索 + RRF + 重排 + 阈值

新增 `HybridSearchService`（或扩展 `SearchRepository`），查询流水线：

```
查询理解(可选, Foundation Models @Generable)：自然语言 → {year, country, city, content语义词}
  ├─ 结构化分面 → 精确 SQL 过滤（join photo_tags type=city/year ...）
  └─ 语义词 → 两路召回
稠密路：activeModel.textEmbedding(归一化) → vec_<model> KNN(k=200) → 按该模型 sim_threshold 卡低分
稀疏路：photo_search_fts MATCH → bm25() 排序，取 200
RRF 融合：score = Σ 1/(rrf_k + rank_i)，rrf_k=60，按 photo 聚合
最终阈值：融合分 ≥ min_fused（双保险）
重排(可选)：Top-N 用归一化 (α·sim + β·bm25) 精排
```

**工程注意**（诚实提示）：部分 sqlite-vec 版本不支持把 `MATCH ... AND k=` 放进 CTE / 参与 JOIN。**稳妥实现**：分两条查询——先 `nearest` 拿 `(photoID, sim, rank)`，再 FTS 拿 `(photoID, rank)`，在 **Swift 层做 RRF 融合 + 阈值**（逻辑与 SQL 版一致）。本项目现状正是分步调用（`PhotoLibraryViewModel.semanticSearch`），故优先走 Swift 融合，先跑通再谈 SQL 内联。

### 6.4 阈值标定

- 每模型 `sim_threshold` 不能拍脑袋：准备一批 query + 人工判定相关/不相关样本，扫阈值看 precision/recall，取精度拐点写 `embedding_spaces.sim_threshold`。
- MobileCLIP2 与 JINA 分数分布不同，各标各的；先取保守初值（CLIP 系余弦常落 0.2~0.35），再按实测调。

### 6.5 搜索入口收敛

- `semanticSearch` 不再「直接展示全部 KNN」，改为调 `HybridSearchService`，受阈值约束、与 Find 浮层关键词/标签/时间筛选融合，而非仅在「相似模式」替换照片墙。
- `searchSimilar`（以图搜图）保持独立，走 `similarityProvider`（Apple FP）。

### 6.6 「相似照片」结果：阈值替代固定 Limit + 置信度角标（已落地）

- `AnalysisDataRepository.nearest` 新增 `minScore` 参数：传入时按 `score >= minScore` 过滤，**不再二次截断数量**（`limit` 仅作为 KNN 候选池上限，sqlite-vec 要求显式 k）；结果始终按相似度降序。
- `searchSimilar`：候选池 `limit=2000`、`minScore = PhotoLibraryViewModel.similarPhotoMinScore`（当前 `0.6`，FeaturePrint 余弦相似度，仅展示相关性较高的结果），去掉旧的固定 `limit=200`。`0.6` 为初始保守值，待 §6.4 阈值标定流程跑通后可按实测调整（与 `embedding_spaces.sim_threshold` 的标定方法一致）。
- `PhotoSearchResult` 新增 `similarityScore: Double?`；`searchSimilar` 把 `VectorMatch.score` 按 photo id 映射回结果。
- UI：`PhotoGridItem` 新增右下角角标，相似模式下显示 `"\(Int(score*100))%"`（如 `82%`），与左下角媒体类型标签、右上角美学/综合评分角标互不遮挡。

## 8. 风险与边界

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 既有向量是 L2/未归一化 | 阈值与 RRF 稠密路不可信 | M1 先行，一次性重建索引 |
| MobileCLIP2 / JINA / Gemma 维度未定 | 建表维度占位 | 建表按 `embedding_spaces.dimension` 动态生成，不写死；接入时回填 |
| MapKit 仍可能限流 | 大库回填慢 | 聚类去重 + 串行限流 + 退避；只跑 pending/failed |
| sqlite-vec CTE/JOIN 限制 | SQL 内联 RRF 可能报错 | 优先 Swift 层融合（现状已分步调用） |
| 中文词表质量 = 打标命脉 | 标签不准 | 结构化维护（层级+别名），可迭代；改动只重算被改条目 |
| 切换语义模型需全库重索引 | 一次性耗时 | 后台低优、断点续跑；Apple FP 相似空间不受影响始终可用 |
| 用 CLIP 向量做去重会误判 | 不同照片被判重复 | 去重固定走 Apple FeaturePrint（视觉/近重复），CLIP 只做"语义找相似" |
| macOS 27 以 Core AI 取代 Core ML（WWDC 2026） | MobileCLIP2 走 Core ML | 二者共存、无弃用表、`.mlmodel` 仍可用；现按 Core ML 接入，后续迁移 Core AI |
| 5 万张存储 | 双模型双副本约 500MB | 量级可忽略；确认 sqlite-vec 稳定后去掉 BLOB 副本减半；百万级再上 int8 量化 |
