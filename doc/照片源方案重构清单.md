# MantaPhotos 照片源方案重构清单

目标：把当前「只对接 macOS 系统图库（Photos / PhotoKit）」的单一数据来源，重构为**可插拔的多照片源架构**，支持：

1. 系统图库（现状，保留）；
2. 本地目录（用户选择的文件夹，内含照片 / 视频）；
3. 非系统照片库（其它 `.photoslibrary` 包或第三方导出目录——按文件级访问处理，见边界说明）。

> 本文是**设计与改造清单**。所有结论基于对当前代码的实际盘点（文件 / 符号已标注）。

> 实现状态（2026-06-09，M1–M5 已落地，未在本环境编译）：见文末「实现记录」。核心架构（PhotoSource 抽象 / 注册表 / 多源数据库 / 本地目录源 / 评分与缩略图路由 / 源管理 UI）已按本清单实现，需在 Mac 上 `xcodebuild` 验证。

---

## 0. 一句话结论（先看这条）

当前整套数据流把「资产身份」死绑在 `PHAsset.localIdentifier` 上——它同时是领域模型的 `id`、数据库主键、缩略图 / 原图 / 视频 / Live Photo / 收藏 / 删除的唯一入口，以及评分任务的定位键。要支持多源，核心动作只有一句：**把「资产身份」与「资产定位 / 取数」从 PhotoKit 解耦，抽象出 `PhotoSource`，让 PhotoKit 只是其中一个实现。** 数据库已经预留了 `source_type` 列（但未启用），是个好起点。

## 1. 现状盘点：与系统图库的耦合点

| 维度 | 位置 | 耦合点 |
| --- | --- | --- |
| 资产身份 | `Domain/PhotoAsset.swift` | `id` 直接等于 `localIdentifier`（见 `PhotoLibraryAdapter.map`，`id: asset.localIdentifier`）；模型里**没有任何「源」字段**。 |
| 数据库主键 | `Infrastructure/Database/DatabaseMigrator.swift` | `photo_assets.id` 用 localIdentifier；`local_identifier text not null unique`。已存在 `source_type default 'photos_library'`（迁移 3），但**未被领域模型与查询使用**。 |
| 写库 | `Infrastructure/Database/PhotoAssetRepository.swift` | `upsert` 把 `source_type` **硬编码**为 `"photos_library"`；`device_category` 仅按截图判定。 |
| 缩略图 | `Infrastructure/Photos/PhotoThumbnailProvider.swift` | 全部走 `PHCachingImageManager` + `PHAsset.fetchAssets(withLocalIdentifiers:)`。 |
| 原图 / 视频 / Live | `Infrastructure/Photos/PhotoLibraryAdapter.swift` | `requestImageData` / `requestAVAsset` / `requestLivePhoto` 全部按 localIdentifier 取 `PHAsset` + `PHImageManager`。 |
| 写操作 | `PhotoLibraryAdapter.setFavorite / deleteAsset` | 走 `PHPhotoLibrary.performChanges`，只对系统库有效。 |
| 导入 | `Domain/PhotoLibraryImportUseCase.swift` | `fetchAssetCount` / `fetchAssets` 是 PhotoKit 专属枚举；分阶段导入逻辑与 PhotoKit 绑定。 |
| 评分取数 | `Domain/AnalysisScheduler.swift` + `Infrastructure/Database/AnalysisRepository.swift` | `pendingVisionTasks` 直接 `select photo_assets.local_identifier`；`scheduler.score` 用 `adapter.requestImageData(localIdentifier:)` 取像素。 |
| 变更监听 | （缺失） | 未实现 `PHPhotoLibraryChangeObserver`；本地目录则完全没有文件监听。 |
| 权限 / 沙盒 | `Xcode/MantaPhotosMac.entitlements` | 仅 `app-sandbox` + `personal-information.photos-library`；**没有任何用户选择文件 / 书签 entitlement**。 |
| 用途声明 | `Xcode/Info.plist` | 只有 `NSPhotoLibraryUsageDescription` / `AddUsageDescription`。 |
| 查看器 | `Presentation/Photos/PhotoViewerView.swift` | 直接调用 adapter 的 `requestAVAsset` / `requestLivePhoto`，按 localIdentifier。 |

结论：耦合集中在 **3 个基础设施文件**（`PhotoLibraryAdapter`、`PhotoThumbnailProvider`、`AnalysisRepository`/`AnalysisScheduler`）+ **1 个领域模型**（`PhotoAsset`）+ **导入用例**。上层 ViewModel / UI 基本只认 `PhotoSearchResult`，改造面相对可控。

## 2. 目标能力与边界

支持：

- 系统图库（保留全部现有能力：Live Photo、视频、收藏 / 删除写回系统、iCloud 状态）。
- 本地目录：递归扫描用户选定文件夹中的图片 / 视频；缩略图、预览、原图、视频播放、AI 评分；本地"收藏"（App 内）、"删除"（移入废纸篓）。
- 非系统照片库：作为**只读文件目录**接入（扫描其 originals / Masters 等媒体文件）。

明确边界（写进文档避免后续误期）：

- **PhotoKit 只能访问系统图库**。其它 `.photoslibrary` 包**无法**用 `PHPhotoLibrary` 打开，因此「非系统图库」只能走文件级访问，拿不到系统库的相册结构、人物、Live Photo 配对等托管信息（需自行从文件配对推断）。
- 本地源**无法写回系统收藏 / 系统相册**；收藏、回收站均为 App 内语义。
- 本地源的 Live Photo 需靠 `.heic + .mov` 同名配对（Apple 导出）或 Google Motion Photo（单文件内嵌）推断，覆盖度有限。

## 3. 架构层改造：`PhotoSource` 抽象

### 3.1 核心协议（建议）

```text
PhotoSource              // 一个照片源的身份与能力声明
 ├─ id / kind / displayName / 是否只读 / 是否支持写回系统
 ├─ AssetEnumerator      // 枚举资产快照（替代 fetchAssets / fetchAssetCount）
 ├─ MediaResourceProvider// 缩略图 / 预览 / 原图 data / AVAsset / LivePhoto
 ├─ AssetMutator         // setFavorite / trash / delete（按源实现或抛"不支持"）
 └─ SourceChangeObserver // 变更监听（PhotoKit 观察者 / FSEvents）
```

- `MediaResourceProvider` 是**取像素的唯一入口**：评分、缩略图、查看器都改为依赖它，而不再各自 `import Photos`。
- 三个适配器：`SystemPhotosSource`（包装现有 `PhotoLibraryAdapter` / `PhotoThumbnailProvider`）、`LocalDirectorySource`、`ExternalLibrarySource`（可先用 `LocalDirectorySource` 复用）。

### 3.2 资产标识模型（最关键）

废除「`id == localIdentifier`」假设，改为：

- `photo_assets.id`：源内稳定主键，建议 `"{source_id}:{source_asset_key}"` 或新生成的 UUID（推荐前者，便于幂等 upsert 与人读）。
- `source_id`：FK → 新表 `photo_sources`。
- `source_asset_key`：源内定位键——系统库为 `PHAsset.localIdentifier`；本地源为相对路径 + 内容指纹。
- `(source_id, source_asset_key)` 建唯一索引。
- 本地源额外存 `file_bookmark`（安全作用域书签）、`relative_path`、`content_hash`、`file_size`。

### 3.3 组合根

`AppState` / `PhotoLibraryViewModel` 持有「当前激活源集合」与一个 `PhotoSourceRegistry`；查询默认聚合所有启用源（或按源筛选，见 UI）。

## 4. 数据库层改造

新增表 `photo_sources`：

```text
photo_sources(
  id text primary key,
  kind text not null,            -- system_photos | local_directory | external_library
  display_name text not null,
  root_bookmark blob,            -- 本地源：安全作用域书签
  root_path text,                -- 展示用
  is_enabled integer not null default 1,
  last_synced_at text,
  created_at text, updated_at text
)
```

`photo_assets` 改造（新迁移，版本 5）：

- 新增 `source_id text references photo_sources(id)`、`source_asset_key text`、`file_bookmark blob`、`relative_path text`、`content_hash text`、`file_size integer`。
- 建唯一索引 `unique(source_id, source_asset_key)`；保留 `local_identifier` 但允许为空（本地源无）。
- 回填迁移：插入一行 `photo_sources(kind='system_photos')`，把现有所有 `photo_assets.source_id` 指向它，`source_asset_key = local_identifier`。
- 取消 `local_identifier not null unique` 约束（本地源没有），唯一性改由 `(source_id, source_asset_key)` 保证。

下游表（`photo_scores` / `analysis_tasks` / `photo_search_documents` / `albums` / …）都以 `photo_assets.id` 外键关联，主键策略不变即可继续工作——这是把 `id` 设计成稳定键的最大收益。

收藏 / 回收站语义按源区分：系统源写回系统；本地源只更新 `is_favorite` / `in_trash`（已有列）。

## 5. 系统 API 调用改造

### 5.1 沙盒与权限

- entitlements 增加：`com.apple.security.files.user-selected.read-write`、`com.apple.security.files.bookmarks.app-scope`（持久化书签）。
- Info.plist 视需要补充文件访问相关说明文案（用户可读）。
- 选目录：`NSOpenPanel`（`canChooseDirectories = true`）。
- 持久访问：保存 `bookmarkData(options: .withSecurityScope)`；使用前 `url.startAccessingSecurityScopedResource()`，用完 `stop...`。

### 5.2 本地媒体读取（替代 PhotoKit）

- 缩略图：`QuickLookThumbnailing.QLThumbnailGenerator`（系统级、支持视频首帧 / RAW / HEIC），或 `ImageIO` 的 `CGImageSourceCreateThumbnailAtIndex`；自建内存 LRU + 磁盘缓存（PhotoKit 那套 `PHCachingImageManager` 缓存对本地文件不可用）。
- 原图 data：直接读文件（`Data(contentsOf:)`，注意安全作用域）。
- 视频：`AVURLAsset(url:)` 直接喂给 `VideoPlayer`。
- Live / Motion Photo：`.heic + .mov` 同名配对组装 `PHLivePhoto`（`PHLivePhoto.request(withResourceFileURLs:...)`）；Google Motion Photo 需解析内嵌偏移，覆盖度有限，可先降级为静态图。
- 元数据：`ImageIO` `CGImageSourceCopyPropertiesAtIndex` 取 EXIF 创建时间 / 像素尺寸 / 设备 make-model（喂 `device_category` 推断）；`AVAsset` 取时长。
- 写操作：本地"删除"用 `FileManager.default.trashItem(at:resultingItemURL:)`（移入废纸篓，可恢复，符合现有 App Trash 语义）。

### 5.3 变更监听

- 系统源：补 `PHPhotoLibraryChangeObserver`（当前缺失，顺带补上增量同步）。
- 本地源：`FSEventStream` 或 `DispatchSource`（`makeFileSystemObjectSource`）监听根目录增删改，触发增量重扫。

## 6. 代码层改造（按文件）

- `Domain/PhotoAsset.swift`：加 `sourceID`、`sourceAssetKey`（及本地源的 `fileURLProvider` / `relativePath`）。`isScreenshot` 现依赖 `PHAssetMediaSubtype`，本地源需另立判定（按尺寸 / 文件名 / 无 EXIF 相机信息）。
- `Infrastructure/Photos/PhotoLibraryAdapter.swift`：抽出 `SystemPhotosSource` 实现 `PhotoSource` 协议，行为不变。
- `Infrastructure/Photos/PhotoThumbnailProvider.swift`：改为按 `sourceID` 路由——系统走 `PHCachingImageManager`，本地走新的 `LocalThumbnailProvider`。对外接口从 `localIdentifier` 改为 `PhotoAsset` / `(sourceID, key)`。
- `Domain/PhotoLibraryImportUseCase.swift`：抽象为 `SourceImporter` 协议；`SystemPhotosImporter`（现逻辑）+ `LocalDirectoryImporter`（递归扫描 + 配对 + 元数据提取 + upsert）。
- `Infrastructure/Database/AnalysisRepository.swift`：`pendingVisionTasks` 不再只返回 `local_identifier`，改为返回 `sourceID + sourceAssetKey`（或整个定位描述）。
- `Domain/AnalysisScheduler.swift`：`score` 改为通过 `MediaResourceProvider.imageData(for:)` 取像素，不再直接 `requestImageData(localIdentifier:)`。
- `Infrastructure/Database/PhotoAssetRepository.swift`：`upsert` 写真实 `source_id` / `source_asset_key`，不再硬编码 `"photos_library"`。
- `Infrastructure/Database/SearchRepository.swift`：行映射补 source 字段；筛选支持「按源」过滤。
- `App/PhotoLibraryViewModel.swift`：多源管理（添加 / 移除本地目录、启停源、聚合或按源刷新）。
- `Presentation/Photos/PhotoViewerView.swift`：媒体请求改走 `MediaResourceProvider`。
- UI 新增「照片源」管理入口（建议放 `SettingsPageView` 或侧栏顶部 source list）：添加本地目录、查看 / 移除源、显示同步状态。

## 7. 迁移与兼容

- 数据库迁移版本 5：建 `photo_sources`、扩 `photo_assets`、回填系统源、改唯一约束。**单向且幂等**，不破坏已有评分 / 搜索数据。
- 现有所有功能在「系统源」单源下行为不变（回归基线）。
- 旧 `source_type` 列可保留作冗余展示，或在迁移 5 中并入 `source_id` 后弃用。

## 8. 风险与权衡

- **性能**：本地缩略图没有 PhotoKit 的托管缓存，需要自建缓存 + 后台预热，否则大目录滚动会卡（参考现有网格预热策略，复用节流思路）。
- **安全作用域书签**：必须严格配对 start/stop，泄漏会导致文件句柄耗尽；沙盒下书签失效（如目录被移动）需有重新授权流程。
- **Live Photo 覆盖度**：本地配对不完整，需明确降级策略。
- **唯一性 / 去重**：同一文件可能同时存在于系统库与本地目录，需用 `content_hash` 做跨源去重策略（或允许重复并标注来源）。
- **截图 / 设备分类**：本地源无 `PHAssetMediaSubtype`，分类准确度下降，需 EXIF 兜底。

## 9. 分阶段实施建议

- **M1 解耦地基**：引入 `PhotoSource` / `MediaResourceProvider` 协议；把现有 PhotoKit 代码收进 `SystemPhotosSource`；评分 / 缩略图 / 查看器改为依赖协议。功能零变化，纯重构（可单独编译验证）。
- **M2 数据库多源**：迁移 5 + 仓储改造 + 回填系统源。
- **M3 本地目录源（只读）**：entitlements + NSOpenPanel + 书签；本地扫描 / 缩略图 / 预览 / 视频 / 评分跑通。
- **M4 本地写操作 + 监听**：废纸篓删除、App 内收藏、FSEvents 增量同步；系统源补 `PHPhotoLibraryChangeObserver`。
- **M5 非系统图库 + 跨源去重 + 源管理 UI**：Live/Motion 配对、content_hash 去重、设置页源管理。

## 10. 给重构执行者的提示

动手时从 **M1** 开始，且第一刀切在 `MediaResourceProvider`——只要评分与缩略图不再 `import Photos`，后续每个源都是「加实现」而非「改调用方」。`photo_assets.id` 设计成 `{source_id}:{source_asset_key}` 后，所有下游外键表无需改主键，这是把改造面压到最小的关键。

## 实现记录（2026-06-09，M1–M5）

> 在 Linux 沙箱完成，**无 macOS/Swift 工具链，未真实编译**；已做括号 / 引号配平、符号与调用点全量交叉核对。Swift 6 严格并发与 GRDB / AVFoundation 细节请在 Mac 上 `xcodebuild` 验证。

新增文件：

- `Domain/PhotoSource.swift`：`PhotoSourceKind` / `PhotoSourceDescriptor` / `ThumbnailRequestToken`（抽象掉 `PHImageRequestID`）/ `PhotoSourceRegistry`（sourceID→类型 + 已解析的安全作用域根 URL，NSLock 跨线程）/ `PhotoSourceError`。
- `Infrastructure/Database/PhotoSourceRepository.swift`：`photo_sources` 表 CRUD（含级联删除源及其资产）。
- `Infrastructure/Sources/LocalMediaSupport.swift`：`LocalThumbnailProvider`（ImageIO 降采样 + NSCache + 视频首帧）/ `LocalMediaProvider`（评分取像素：图片读文件、视频取帧转 JPEG）/ `CancellationBox` / `LocalMediaType`。
- `Infrastructure/Sources/LocalDirectoryImporter.swift`：递归扫描 + ImageIO 尺寸/EXIF 时间 + 批量 upsert（Sendable，可后台执行）。

改动：

- `PhotoAsset`：新增 `sourceID / sourceAssetKey / relativePath / contentHash / fileSize / isScreenshotFlag`（带默认值，旧构造点不破）。
- 数据库 migration 5：建 `photo_sources`、`photo_assets` 增补 source 字段、回填系统源、`(source_id, source_asset_key)` 唯一索引；**不重写 id**，系统行 id 仍 = localIdentifier，本地行 id = `"{sourceID}:{relpath}"` 且 local_identifier 同值（满足历史 not null unique）。
- `PhotoAssetRepository.upsert` / `SearchRepository.map`：读写 source 字段。
- `AnalysisRepository.pendingVisionTasks` + `AnalysisScheduler.score`：携带源定位，系统走 PhotoKit、本地走文件/视频帧取像素。
- `PhotoThumbnailProvider`：改为按源路由的门面，统一返回 `ThumbnailRequestToken`；`PhotoGridView` / `PhotoViewerView` 改用资产级 API 与 token；网格预热改为按 `PhotoAsset` 维护。
- `PhotoViewerView`：本地视频用 `AVURLAsset` 播放；静态图 / 预览走门面。
- `PhotoLibraryViewModel`：源管理（loadAndRegisterSources / addLocalDirectory / rescanSource / removeSource）、收藏仅系统写回、删除按源（系统走 PhotoKit、本地走 `FileManager.trashItem`）。
- `AppState` bootstrap：加载并注册源、开启本地源安全作用域。
- `SettingsPageView`：「照片源」管理区（列表 / 添加本地文件夹 NSOpenPanel / 重扫 / 移除）。
- entitlements：加 `files.user-selected.read-write` 与 `files.bookmarks.app-scope`。

本轮的保守取舍（覆盖 M1–M5 功能，但部分用稳妥实现）：

- **FSEvents 实时监听**未做，改为「手动重扫」按钮（避免盲写 C API 出错）；后续可补 `FSEventStream`。
- **跨源去重**为基础版：`content_hash` 列已就绪但导入暂不逐文件计算（大库性能考虑），唯一性由 `(source_id, source_asset_key)` 保证。
- **本地 Live Photo 配对**未做（本地资产仅 image/video）。
- **本地视频精确尺寸/时长**导入阶段从略（需异步 `AVAsset.load`，不影响网格与评分）。
- 安全作用域：根目录书签覆盖子文件访问；移除源时未显式 `stopAccessingSecurityScopedResource`（应用退出即释放）。

Mac 上验证重点：migration 5 升级既有库、添加本地文件夹后网格/查看器/评分是否正常、删除本地照片是否进废纸篓、Swift 6 并发是否有 Sendable 报错（缩略图回调、Task.detached 导入）。

## 后续增量（2026-06-12，跨源相关最终态）

在 M1–M5 基础上，与「多照片源」相关的后续改动已落地（仍待 Mac 编译验证）：

- **废片篓批量按源处理**：`PhotoLibraryViewModel` 新增「全部恢复」与「清空」——清空时**系统源走 PhotoKit 批量删除、本地 / 外部源进系统废纸篓（`FileManager.trashItem`）并标记已删除**，与单张删除的按源路由一致。
- **本地视频取帧**：`LocalThumbnailProvider` / `LocalMediaProvider` 改用 macOS 13+ 的异步 `AVAssetImageGenerator.image(at:)`，替代已弃用 / 新 SDK 已移除的 `copyCGImage(at:actualTime:)`（影响本地源缩略图与评分取帧）。
- **跨 actor 安全作用域**：本地源根目录 URL 在 `PhotoSourceRegistry`（NSLock）解析，缩略图 / 查看器 / 评分取图均通过它路由，避免把各 source 标 `@MainActor`，符合 Swift 6 严格并发。
